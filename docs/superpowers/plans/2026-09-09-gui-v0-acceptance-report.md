# GUI v0 验收抽检报告 — accept_10min 球衣颜色一致性

- 日期：2026-09-09
- 结论：**通过**（crop 一致性 97.77% / track 一致性 97.35%，验收门 ≥90%）
- 数据：`data/bili_final_test/accept_10min.mp4`（2024 城市飞盘俱乐部锦标赛决赛 5:00–15:00，1080P30）
- 分析产物：`.worktrees/gui-v0/runs/gui_analysis/accept_10min/tracks.json`（18004 帧 / 396,983 框 / 4,400 track）
- 抽检工具：`tools/team_color_check.py`（HSV 红蓝规则独立于分队算法，每 600 帧抽 1 帧 × 31 帧）

## 方法

分队 team_id 来自独立通道（HSV 颜色特征聚类），本抽检用**另一套独立实现**的 HSV 规则
（`tools/team_color_check.py`）对抽检帧的上半身裁剪判"红衣/蓝衣"，度量：
1. 簇内纯度（crop 一致性）：同队裁剪主色占比；
2. 簇间互斥（cross_team_distinct）：两队主色必须不同；
3. track 级一致性：track 主色与所属队主色一致的比例。
仅统计场地球员（画面下部 y2 ≥ 0.45H 且框高 ≥90px，方案 §8.1 场地过滤的近似）；
判色不明的裁剪（红蓝占比均 <0.15 或接近）单列为 ambiguous，不计入分母。

误判的少数裁剪主要是守门员/裁判（非两队队服）与遮挡帧，属预期噪声，GUI 改判入口可兜底。

## 抽检中发现并修复的问题（这正是抽检的价值）

1. **SigLIP 聚类在本素材按景别/构图而非球衣色分簇**（初版抽检一致性仅 0.519）。
   修复：分队主路改为 HSV 颜色特征（每 track 红蓝占比均值 → KMeans(2)，分离度阈值 0.15），
   SigLIP 降为颜色不可分时的兜底路径——方案选型的偏离已记录在 team.py 模块注释。
2. `team_colors` 颜色推断曾按 KMeans 原始簇索引查表（标号任意会导致红蓝反转），
   改为按簇心实际红蓝占比判色，并新增不受标号影响的单测。
3. pipeline 新增 `--team-only`：换分队算法后免重跑约 50 分钟的跟踪阶段。
