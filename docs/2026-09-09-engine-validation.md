## 验证目的

事件引擎（`frisbee_analyzer/events.py`）此前只有合成轨迹单测（6 项）。本验证检查它在**真实检测/跟踪/分队数据**上的行为，并明确其前置条件。

## 结论（三条，均为实测）

1. **引擎保守、无幻觉**：在缺少真实飞盘轨迹时，它**没有产生任何虚假的持盘/交换手/得分事件**——71 个 `disc_on_ground` 全部来自“无持有者 + 低速持续 N 帧”的判定，符合设计。这是好消息：误报代价高的事件统计不会凭空生成。

2. **但事件统计的硬前提是飞盘轨迹**：持盘判定要求“盘中心落在球员手部区域 + 盘速低于阈值”，而本次输入无飞盘检测（用最高置信度球员代理，盘位置永远在球员身上且随球员移动 → 速度不为 0 → 不满足持盘条件）。**结论：Phase 3 事件统计必须先接入飞盘检测/跟踪管线**（当前 `iter_player_tracks` 只检测 `classes=[0]` 即 person）。

3. **前置条件清单**（据此排期）：
   - ① 飞盘检测接入 worker（`--weights` 支持飞盘模型 + 类别配置）——**最高优先级**
   - ② 单应性标定接入（本验证用画面线性代理，精度不足；真实测速/得分区判定需标定 json）
   - ③ 得分区多边形与攻防方向配置（引擎已支持 `EndZone`，待标定后填入）
   - ④ 用 E6 GT（14 得分/1 攻转）做端到端对齐评测（±90s 容差）

### 发现并修复的 3 个真实 bug

1. **双模型帧错位**：原实现用 `model.track(source=...)` 的 stream 生成器 + 另一个 `cap` 读取，两个解码器节奏不同 → 改为单数据源逐帧喂入。
2. **标定分辨率不匹配无校验**：`load_calibration` 增加 `image_size` 校验与 H 自动缩放（标定在 A 分辨率做的、用于 B 分辨率视频时世界坐标会完全错位）。
3. **场外误检污染事件**：飞盘检测投影到场地外的观测现在被丢弃（`disc_rejected_out_of_field` 计数），防误检伪造事件。

### 关键结论（实测）

- 在 `25866279684-1-192_55-56min.mp4` 上，**135 个飞盘检测全部落在场地外**（画面 y=263-298，而标定覆盖 y=440-578）→ 全部被过滤，事件数为 0。
- **这说明现有飞盘检测器（p2_shadow_v1）在该视频上不可用于事件统计**——不是引擎问题，是检测质量问题（草纹误检）。正在跑的 11s 重训 + 硬负样本迭代正是解药。
- 引擎的保守设计再次验证：**宁可 0 事件，不产生假事件**。
