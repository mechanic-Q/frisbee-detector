## 3. 架构

```
┌─ Windows 原生（GUI 主进程，PySide6，LGPL）────────────────┐
│ gui/main.py               入口 + 主窗口                     │
│ gui/video_player.py       QMediaPlayer + QVideoSink→QImage  │
│ gui/overlay.py            QPainter 叠加（球员框/队伍色）      │
│ gui/worker_process.py     QProcess 管理 + JSON-lines 协议    │
│ gui/calibrate_dialog.py   4/6 点标定（复用 utils/homography）│
│ gui/team_override.py      队伍改判                           │
└──────────────┬───────────────────────────────────────────┘
               │ QProcess: wsl.exe -e python3 -m frisbee_analyzer.pipeline --video …
               │ stdout = JSON-lines（UTF-8）
┌──────────────┴─────────────────── WSL（CUDA，现有环境）────┐
│ frisbee_analyzer/pipeline.py   分析 worker CLI（可独立运行） │
│ frisbee_analyzer/protocol.py   消息 schema + 路径转换        │
│ frisbee_analyzer/team.py       SigLIP+UMAP(3)+KMeans(2)     │
│ frisbee_analyzer/tracking.py   BoT-SORT 球员跟踪             │
│ frisbee_analyzer/events.py     （已有，v0 不接）             │
└───────────────────────────────────────────────────────────┘
```

**worker 管线**：视频 → 人员检测（v0 默认零样本 `yolo26x.pt` classes=[0] conf=0.25 imgsz=1280，`--weights` 可换成日后 player/referee 微调权重，GUI 无需改动）→ BoT-SORT（固定机位配置：`gmc_method=none`、ReID off、`track_buffer≈50`）→ 分队（SigLIP 裁剪 embedding → UMAP(3) → KMeans(2)，每 60 帧重拟合；开球时半场 x 坐标先验自动纠偏 KMeans 标签翻转；裁判候选=出场风格/位置规则过滤，容后微调权重解决）→ 输出 per-video JSON。

**JSON-lines 协议**（`frisbee_analyzer/protocol.py` 定义，两侧共用）：
- worker→GUI：`{"type":"meta","total_frames":N,"fps":30}`、`{"type":"progress","frame":N}`、`{"type":"log","msg":"…"}`、`{"type":"result","path":"…"}`、`{"type":"error","msg":"…"}`
- 取消：GUI 直接 `QProcess.terminate()`/kill（离线批处理，无事务需要协商）。
- 路径转换：GUI 传 Windows 路径，`protocol.py` 提供 `win→wsl`（`E:\x` → `/mnt/e/x`）双向 helper；worker 以 `PYTHONUTF8=1` 启动防编码坑。

**输出 JSON**（COCO-video 风格，落 `runs/gui_analysis/<video_stem>/tracks.json`，runs/ 已 gitignore）：
```json
{"video": "…", "fps": 30, "frames": {"1000": [{"track_id": 3, "team_id": 0,
  "bbox": [x1, y1, x2, y2], "conf": 0.87}]}, "team_overrides": {"3": 1}}
```
`team_id`：0=红 1=蓝 2=裁判 3=旁观/忽略（与 `tools/auto_label_roles.py` 的角色编码一致）。字段满足 events.py 的输入形态（后续可加世界坐标 x,y）。

**队伍改判**：GUI 修改 track 的 team_id → 更新 `team_overrides` 并原子写回 JSON（每步落盘，沿用 review 工具的"决策即保存"惯例）。

## 4. 里程碑

- **M1 worker 骨架**：`pipeline.py` + `protocol.py` + BoT-SORT 跟踪移植；CLI 独立可跑，`tests/test_protocol.py`（消息 schema、路径转换）。完成标志：WSL 手跑 1 分钟片段出 tracks.json。
- **M2 分队模块**：`team.py`（合成 embedding 单测 `tests/test_team.py`：两簇可分、先验纠偏翻转、60 帧重拟合）；接入 worker 出 team_id。
- **M3 GUI 壳**：视频打开/播放/逐帧步进 + 启动分析（进度/取消）+ tracks.json 叠加回放（Windows 侧 `pip install PySide6`）。若 QMediaPlayer 对该素材解码有问题，备选 OpenCV 逐帧 + QImage（容忍轻微性能损失）。
- **M4 标定 + 改判**：标定对话框（4/6 点、RANSAC、误差显示、叠加/鸟瞰验证、保存加载）+ 队伍改判入口。
- **M5 验收与合流**：10 分钟视频端到端；分队抽检 ≥90%（抽 3 个时间点 × 各 20 框人工比对）；ID 跳变记录到 `docs/`；更新 AGENTS.md（GUI 用法一节）。通过后并回 `feat/match-analysis`。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| QMediaPlayer 解码 1080P30 兼容性 | 备选 OpenCV 逐帧 + QImage；决策记录进 AGENTS.md |
| wsl.exe 桥接：编码/缓冲/僵尸进程 | PYTHONUTF8=1；QProcess 读端按行 flush；异常退出时 worker 栏显式报错 |
| 相近球衣色 KMeans 不稳 | 半场先验纠偏 + GUI 人工改判兜底（本来就是产品功能） |
| 零样本人员框质量一般（28–32 框 vs 真值 14–25） | v0 验收只看"管线通 + 队伍色可辨"，框质量留给 player/referee 微调 |
| 跨 worktree 数据不可见 | 一律绝对路径 + 协议内转换；禁止在 GUI 会话里拷贝数据进 worktree |
